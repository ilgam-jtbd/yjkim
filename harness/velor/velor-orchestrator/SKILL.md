# velor Orchestrator

velor 업무를 적절한 에이전트로 라우팅하고, 여러 역할이 협업할 때 순서·전달물·검증·승인을 묶는 입구 스킬이다.

## 시작 전
1. `references/velor-context.md`를 먼저 읽는다(BM·퍼널·지표·스택·가드레일).
2. `artifacts/` 존재를 확인해 **초기 실행 / 부분 재실행 / 새 실행**을 분기한다.
   - "다시", "재실행", "보완", "이전 결과 기반", "{부분}만 다시" → 부분 재실행: 기존 산출물을 읽고 변경분만 갱신.

## 실행 모드
| 모드 | 상황 | 처리 |
| --- | --- | --- |
| 빠른 설계 | 가벼운 방향·예시 | 질문 최소화, 단일 에이전트로 바로 라우팅 |
| 함께 설계 | 목표는 있으나 자료 부족 | 핵심 질문 3개 이하로 빈칸 채운 뒤 진행 |
| 실행 하네스 | 여러 역할 협업 필요 | 순서·전달물·검증·사람 승인 게이트를 묶음 |

## 라우팅 (단일 역할이면 바로)
| 요청 신호 | 에이전트 |
| --- | --- |
| 실험·A/B·전환율·z-test·퍼널·채널 예산 | `velor-growth-experiment` |
| 전문가 매칭·리드스코어·아웃리치·자문→채용 전환 | `velor-matching-recruiter` |
| IR·라운드·데이터룸·재무·투자자 Q&A | `velor-ir-advisor` |
| SEO/GEO·광고·CRM·랜딩 카피·소셜 | `velor-content-marketer` |

단일 역할로 충분하고 다른 역할과 토론할 필요가 없으면 에이전트 하나만 호출하고 산출물을 `artifacts/`에 남긴다.

## 협업이 필요할 때 (Agent Team)
2개 이상 역할이 서로 발견을 주고받아야 하면(예: 신규 랜딩 캠페인 = 카피 + 실험 설계 + 리드 측정) 팀으로 묶는다.
1. `TeamCreate` 로 필요한 에이전트를 팀원으로 구성한다(2~4명 권장).
2. `TaskCreate` 로 단계별 작업·의존관계를 등록한다.
3. 팀원은 `SendMessage` 로 발견·충돌을 공유하고, `TaskUpdate` 로 상태를 갱신한다.
4. Orchestrator는 `TaskGet` 으로 지연·차단을 점검한다.
5. 각 팀원은 결과를 `artifacts/{날짜}-{역할}-{산출물}.md` 로 저장한다.
6. Orchestrator가 `artifacts/` 를 읽어 통합하고 사람 승인 지점을 확인한다.
7. 끝나면 `TeamDelete` 로 정리한다.

## 사람 승인 게이트 (필수)
다음은 자동 완료하지 않고 사람 승인 후 실행한다: 외부 발송(알림톡·메일), 광고/예산 집행, 게시·공개, 결제, 실데이터(DB) 변경, IR 외부 제출. Orchestrator는 해당 단계에서 멈추고 "승인 필요"로 표시한다.

## 산출물 계약
- 모든 중간/최종 결과는 `artifacts/` 에 파일로 남긴다. 대화로만 지나가는 단계는 실행으로 보지 않는다.
- 최종 통합 결과는 `artifacts/{날짜}-final-{주제}.md`, 개선점은 `artifacts/improvement-log.md` 에 기록한다.

## 품질 체크
- 수치는 출처·기간·표본과 함께 제시했는가
- 단정과 "미확정(collecting)"을 구분했는가
- 가드레일(과장·개인정보·차별 표현) 위반이 없는가
- 사람 승인 지점이 명확히 표시됐는가
